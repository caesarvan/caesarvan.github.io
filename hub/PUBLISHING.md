# 网页接入与发布标准 v1

生效日期：2026-10-22；目标仓库 caesarvan/caesarvan.github.io。

- 统一入口：https://caesarvan.github.io/hub/ 。保留原 Hexo 根站及已有子站，模块使用独立目录。
- 公共登记表为 hub/modules.json：稳定唯一 id、标题、说明、图标、颜色、group、type、href、order、enabled。修改一处登记表即可同步侧栏、搜索与目录。独立页面 type=page，已有独立站点 type=link。
- 新模块放 hub/pages/<id>/index.html，资源相对页面自身；支持不同前端技术栈，最终必须输出静态文件。Hash 路由支持刷新与分享。
- 公开仓库和部署产物只包含框架。真实财务、投资、行程、邮件、文件索引和个人收藏不得内嵌到 HTML、JavaScript、JSON、source map 或历史快照中。本轮用户选择通过本机导入使用这些数据。
- 财务、投资、旅行接收各自原始 JSON 快照，只在当前页面内存处理；刷新后需重新导入。格式错误应明确报错并保留此前成功载入的资料，提供清除功能。
- 文件与书签导航接收本机 HTML 索引，仅解析文本和链接，不执行原索引脚本。附件需选择本机文件夹后才能打开；导入索引并不等于附件已经可访问。
- 新增模块先校验、检查空状态与本地导入，再提交。发布时验证 HTTP、资源、模块入口和原首页，保存提交、CI 与验收证据。
- 构建产物与真实数据更新分开：源会话负责更新本地快照和稳定导入文件；只有框架变更才发布 GitHub。定时刷新不得把真实快照推入仓库。
- 同源模块必须是自有受信代码；iframe 提供样式和文档隔离，不作为安全边界。外部站点以链接打开。
- 目标仓库目前从 main 分支发布，自动校验与 Pages 发布并行。现有 CI 不是严格的发布前门禁；迁移到 validate → assemble → deploy 时必须把原根站与全部子站一起组装。
- 上游 Hexo 将来全量生成时，须保留 hub/ 与 life-hub-demo/，避免覆盖。
